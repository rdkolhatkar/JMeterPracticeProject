Aggregate Report Parameters : 
1) Samples : It is a total number of users who hit the API or Service. 
2) Average : Average time taken by all the samples to execute specific label. That means if there are 100 api requests, then for each request there will be specific response time, so it is the average of all individual sample response time in MilliSeconds. 
3) Min: Minimum time taken by user to get the response back from the API or Service. 
4) Max: Maximum time taken by user to get the response back from the API or Service. 
5) Error: Percentage of Failed requests per label. 
6) Standard Deviation: This shows the set of exceptional cases which were deviating from the average value of sample response time. The lesser this value more consistent the data. Standard deviation should be less than or equal to half of average time for a label.
7) Throughput: It is the number of request that are processed per time unit(seconds, minutes, hours) by the server. This time is calculated from the start of first sample to the end of the last sample. Larger throughput is better. 
8) 90% Line : 90% of the samples took no more than this time. The remaining samples took at least as long as this. (90th percentile)
9) Median : It is the time in the middle of a set of samples result. It indicates that 50% of the samples took no more than this time. That is the remainder took at least as long.

A session cookie is a small piece of data stored in the browser to remember a user while they are using a website.
1) When you log in to a website, the server creates a session and sends a session cookie to your browser.
2) The browser stores this cookie temporarily and sends it back to the server with every request.
3) This helps the server recognize that the requests are coming from the same logged-in user.
4) Session cookies usually exist only while the browser is open.
5) When you close the browser or log out, the session cookie is usually deleted.

What is correlation in JMeter and Why correlation is needed?
1) Correlation = capturing dynamic value from server response and passing it to next request
2) When you record a script in JMeter, it works fine once. But when you replay it, it may fail. Because websites use dynamic values like:
   -> A) Session IDs
   -> B) CSRF tokens
   -> C) Auth tokens
   These values change every time you run the application.
3) Correlation in JMeter means capturing dynamic values (like session IDs or tokens) from a server response and reusing them in later requests so the test works every time.
   Example: After login, server returns sessionId=ABC123. Next request must send it. Since it changes (XYZ789 next run), we extract it using a Regular Expression Extractor and use ${sessionId}.

JMeter Server Monitoring
1) Host Server : A Host Server is the machine (physical or cloud server) where your website or API is deployed and running.
   It stores your application code, processes incoming requests, sends responses back and may connect to database servers.
   Example :
   If your Spring Boot API is deployed on 'https://myapi.com' then the server running that application is the Host Server.
   Below are the examples of popular Host Server:
   A) Amazon Web Services EC2 — One of the most popular cloud-based virtual servers (IaaS). Widely used for hosting applications.
   B) Microsoft Azure VM — Azure's Virtual Machine service, a direct competitor to AWS EC2, also an IaaS solution.
   C) Google Cloud Run - This is not a traditional host server. It is a serverless container platform (PaaS), meaning you don't manage the underlying server directly. A more accurate Google Cloud equivalent to EC2/Azure VM would be Google Compute Engine (GCE). Cloud Run is better categorized under serverless/container hosting, not a traditional server.
   D) On-Premise Linux Server — A traditional physical server hosted in your own data center or office. On-Premise Linux Server) running Red Hat Enterprise Linux is a very real and common enterprise setup.
2) Client : A Client is the system that sends requests to the server.
   It can be browser (Chrome, Firefox), mobile app, frontend React app, Postman, another backend service, Selenium automation script, RestAssured test
   Example : When you open 'https://amazon.com' your browser is the Client and it sends request 'GET /products' to the server.
   People often say client server, but technically:
   -> Client = requester
   -> Server = responder
   There is not usually a separate thing called “client server” in normal web hosting.
   Sometimes they mean frontend server, application server, proxy server, depending on context.

DEFINITIONS
=======================================================================================================================
| Aspect         | Host Server                                      | Client                                         |
|----------------|--------------------------------------------------|------------------------------------------------|
| Definition     | A machine (physical or cloud) that stores,       | Any device or application that sends a         |
|                | runs and serves your application or API.         | request to the Host Server and consumes        |
|                | It listens for incoming requests and sends       | the response returned by it.                   |
|                | back responses.                                  |                                                |
=======================================================================================================================

EXAMPLES
=======================================================================================================================
| Aspect         | Host Server                                      | Client                                         |
|----------------|--------------------------------------------------|------------------------------------------------|
| Website        | Apache / Nginx server serving HTML files         | Browser (Chrome, Firefox, Safari)              |
| API            | Spring Boot API running on AWS EC2               | React App / Mobile App / Postman               |
| Cloud          | AWS EC2, Azure VM, Google Compute Engine         | Another microservice calling your API          |
| On-Premise     | Linux Server in your data center                 | Frontend application consuming your API        |
| Database       | MySQL / PostgreSQL Server                        | Spring Boot App querying the database          |
=======================================================================================================================

FUNCTIONS
=======================================================================================================================
| Aspect         | Host Server                                      | Client                                         |
|----------------|--------------------------------------------------|------------------------------------------------|
| Primary Job    | Listen for incoming requests on a port           | Initiate and send requests to the server       |
| Processing     | Processes the request and executes logic         | Waits for the response from the server         |
| Data           | Stores application code, files, data             | Displays or uses the data received             |
| Communication  | Responds back to the client                      | Sends HTTP/HTTPS requests (GET, POST etc.)     |
| Database       | Connects and queries the database                | Does not directly access the database          |
| Availability   | Runs 24/7, always listening                      | Connects only when needed                      |
=======================================================================================================================

FEATURES
=======================================================================================================================
| Aspect         | Host Server                                      | Client                                         |
|----------------|--------------------------------------------------|------------------------------------------------|
| Who starts?    | Waits and listens (passive start)                | Initiates the communication (active start)     |
| Location       | AWS, Azure, GCP, On-Premise Data Center          | User's browser, mobile device, another server  |
| IP Address     | Has a fixed/static IP or domain name             | May have dynamic IP                            |
| Port           | Listens on a specific port (e.g., 8080, 443)     | Uses a random port to send requests            |
| Accessibility  | Accessible to multiple clients simultaneously    | Accesses one or more servers as needed         |
| Security       | Manages firewalls, SSL certificates, auth        | Sends credentials/tokens in request headers    |
| Scalability    | Can be scaled up/out to handle more traffic      | Independent of server scaling                  |
=======================================================================================================================

ROLES IN WEB & API HOSTING
=======================================================================================================================
| Aspect         | Host Server                                      | Client                                         |
|----------------|--------------------------------------------------|------------------------------------------------|
| In Website     | Serves HTML, CSS, JS files to browser            | Browser renders the received files             |
| In REST API    | Processes API calls, returns JSON/XML            | React/Angular app or mobile app calls the API  |
| In Microservice| Acts as service provider for other services      | Acts as service consumer calling other APIs    |
| In Database    | Stores and manages data (MySQL, PostgreSQL)      | Application server querying the database       |
