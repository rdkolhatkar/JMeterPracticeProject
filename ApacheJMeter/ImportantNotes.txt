Install Apache JMeter
1) Open the Jmeter Official download page 'https://jmeter.apache.org/download_jmeter.cgi'
2) Under “Binaries” section click the ZIP or TGZ link
3) Download the "apache-jmeter-5.6.3.zip"
4) Extract the Zip file "apache-jmeter-5.6.3.zip"
5) Navigate To "/apache-jmeter-5.6.3/apache-jmeter-5.6.3/bin" and double-click on "ApacheJMeter" executable JAR (Java ARchive) file.
6) It will Open the ApacheJMeter GUI.

Create Test in JMeter
1) Open the JMeter Graphical User Interface (GUI) 
2) Right click on the "Test Plan" Option (Refer the Image '01_BasicJMeterSetUp' from 'ApacheJMeter\ImportantImages\BasicJMeterSetUp\01_BasicJMeterSetUp.PNG')

FireFox Browser SetUp 
1) Download and Install FireFox Browser from their official downloads page "https://www.firefox.com/en-US/?utm_campaign=SET_DEFAULT_BROWSER"
2) Open the FireFox Browser and click on "open application menu"
3) Navigate to Settings -> General -> Network Settings -> Open the Network Settings Tab -> Connection Settings
4) After opening the "Connection Settings" click on "Manual proxy configuration" radio button
5) Set Http and Https proxy as "127.0.0.1" and port as "8888" 
6) Prot number of Http and Https proxy should be same as that of JMeter port. Default: 8888
7) Once the proxy SetUp is done then Firefox browser will not work properly unless we start the JMeter recording
8) With default Jmeter configuration we can access the "http" requests but for "https" we need to configure the trusted certificate from Jmeter
9) To setup the certificate start the recrding on JMeter then we will receive message saying that "Root CA certificate ApacheJMeterTemporaryRootCA created in JMeter bin directory"
10) Then We have to install that certificate in the FireFox Browser.
11) Navigate to Settings -> Privacy & Security -> Certificates -> View Certificates -> Certificate Manager
12) Click on Import Certificate From location: D:\JMeterPracticeProject\apache-jmeter-5.6.3\apache-jmeter-5.6.3\bin 
13) Then you will be navigated to a pop-up where you have to click on all check boxes for Trusting this JMeter Certificate
14) Click on OK button after you enable all check boxes and now Firefox setup is ready.
15) Refer the FireFox SetUp images from folder "ApacheJMeter\ImportantImages\FirefoxBrowserSetUp"

Chrome Browser SetUp with BlazeMeter Plugin
1) Open the Google Chrome and search for "BlazeMeter plugin" in the search bar 
2) Click on the first link and it will show you the extension inside the "Chrome Web Store"
3) Click on the "add chrome extension" button and it will install the BlazeMeter into the Chrome Browser. 
4) After that click on the "BlazeMeter" icon and cleck on "Sign Up button"
5) Enter first name, last name, email and complete the account creation process, after which you will be navigated to the Home page of BlazeMeter
6) Restart your Chrome Browser and click on plugins option there you will see the Blazemeter plugin, pin that to Chrome titlebar
7) Click on the BlazeMeter plugin on chrome title bar and click on red button to start recording. 
8) After recording is started, open new tab and navigate to the "https://blazedemo.com"
9) Click on the "Choose your departure city" dropdown and select "Boston"
10) Then Click on the "Choose your destination city" dropdown and select "London"
11) Then click on "Find Flight" button.
12) Now all these actions would be recorded into the BlazeMeter and from there you can download the ".jmx" file
13) Now import that .jmx file into JMeter WorkBench.
14) Click on File -> Open -> demo.jmx this flow woll open your .jmx file into the JMeter. 
15) Click on "Thread Group" and then click on "Test" there you will see all the recorded scripts.

Creating the Thread Group
1) Right click on the "Test Plan" and Navigate to 'Add' -> 'Threads (Users)' -> 'Thread Group'
2) Set the 'Thread Properties' like 'Number of Threads (Users)', 'Ramp Up Period (Seconds)' or Duration
3) Then move (Cut + Paste) your ".jmx" files from 'HTTP(s) Test Script Recorder' to 'Thread Group'

Adding Listeners to view and record the load testing results
Note: Listeners in JMeter are used to collect, display and store performance test results. They provide metrics such as response time, throughput, error rate and latency. During script development we use View Results Tree for debugging, but during actual load execution we remove heavy listeners and use Simple Data Writer to store results for later analysis.
1) Right Click on 'Test Plan' -> 'Add' -> 'Listener' -> {1) View Results Tree 2) Aggregate Report 3) Graph Results}
2) Run the JMeter test by providing the appropriate values of Number of Thread, RampUp period and duration of seconds etc. 
3) View the results by clicing on  {1) View Results Tree 2) Aggregate Report 3) Graph Results}

Download and Install External Jmeter Plugins 
1) To download JMeter plugins go to their official Plugin Manager WebSite : https://jmeter-plugins.org/wiki/PluginsManager/
2) To download and install plugins we have to connect the JMeter with JMeter Plugin manager Website
3) To connect JMeter with Plugin Manager we have to first Download the Plugin Manager jar file 
4) Save that downloaded jar into Apache JMeter's "lib/ext" directory and then restart the JMeter app
5) After restarting the JMeter you will see the "Plugin Manager" option under the "Options" menu on Tool Bar. 
6) After clicking on plugin manager it will open separate window then on that window click on "Available Plugins" tab and then in the search box you can search any plugin you want. 
7) Select the checkbox of the Plugin which you want to install and then click on "Apply and Restart" button, it will restart JMeter app.

JMeter Controllers
0) JMeter controller is nothing but a container where we will store all your requests, it's a folder where we will save all our HTTP requests. 
1) Simple Controller is nothing but a folder where we will store all our related HTTP requests, it's an organizational container where we will group and manage our requests without changing their execution.
2) Loop Controller is nothing but a container where we will store all our requests that need to repeat, it's a folder where we will save our HTTP requests to run them a fixed number of times.
3) Once Only Controller is nothing but a container where we will store all our requests that should run only one time, it's a folder where we will save our login HTTP requests to execute them once per thread.
4) Interleave Controller is nothing but a container where we will store all our requests and pick one at a time in order, it's a folder where we will save our HTTP requests to execute them one by one in rotation.
5) Random Controller is nothing but a container where we will store all our requests and randomly pick one to run, it's a folder where we will save our HTTP requests to execute one random request per iteration.
6) Random Order Controller is nothing but a container where we will store all our requests and run all of them in a random order, it's a folder where we will save our HTTP requests to shuffle and execute every request each iteration.
7) Throughput Controller is nothing but a container where we will store all our requests and control how frequently they run, it's a folder where we will save our HTTP requests to execute them based on a percentage or count.
8) Runtime Controller is nothing but a container where we will store all our requests and run them for a fixed time duration, it's a folder where we will save our HTTP requests to keep executing them for a set number of seconds.
9) If Controller is nothing but a container where we will store all our requests that run only when a condition is true, it's a folder where we will save our HTTP requests to execute them based on a variable or expression check.
10) While Controller is nothing but a container where we will store all our requests that keep running until a condition becomes false, it's a folder where we will save our HTTP requests to repeat them in a loop until a variable changes.
11) Switch Controller is nothing but a container where we will store all our requests and route execution to one specific child based on a value, it's a folder where we will save our HTTP requests to direct traffic by matching a variable.
12) ForEach Controller is nothing but a container where we will store all our requests that run once for each value in a variable list, it's a folder where we will save our HTTP requests to iterate over a set of values one by one.
13) Transaction Controller is nothing but a container where we will store all our requests and measure their total combined response time as one unit, it's a folder where we will save our HTTP requests to track the full end-to-end time as a single transaction.
14) Module Controller is nothing but a container where we will store a reference to a reusable Test Fragment, it's a folder where we will point to our saved HTTP requests to reuse the same login or common flow across multiple Thread Groups.
15) Recording Controller is nothing but a container where we will store all our recorded HTTP requests automatically, it's a folder where JMeter will save all our captured browser requests when we record a live session through the proxy.
